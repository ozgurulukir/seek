# seek v0.6.1

## Highlights

- **Keyword search no longer silently drops common English words.** In the default (`parsed`) query mode, `body`, `city`, `study`, and their inflections returned nothing because the query analyzer turned their Porter stem (`bodi`, `citi`, `studi`) into a `stem*` FTS5 prefix. The index is unstemmed, so a stem that is not a prefix of the surface word can never match — such terms are now left as their surface form. The failure was visible in keyword-first (`--lex`, no embedding provider) mode; hybrid search masked it behind the vector leg. (issue #98)
- **`seek sync --json` and `seek_capabilities` now agree with reality.** A run that embedded (or deliberately skipped) chunks is no longer reported as `embeddings: "not_run"`, and a provider the offline/privacy policy refuses to reach is reported as unavailable.
- **The local semantic service starts dramatically faster.** Importing `sentence_transformers` was JIT-compiling numba dispatchers for 10+ minutes; disabling numba's JIT (which the tagger never uses) drops startup to ~38 seconds. (issue #95)

## Fixed

- **Non-prefix Porter stems (issue #98).** `AnalyzeForQuery` now only emits a `stem*` expansion when the stem is a genuine prefix of the surface token (or shorter, which preserves Turkish root reconstruction such as `kitabı`→`kitap`); otherwise it falls back to the surface token. Covered by analyzer and `ToFTS5` unit tests plus an end-to-end parsed-mode regression test that indexes "body of the study and the city" and searches `body`/`study`/`city`.
- **`seek sync` embedding outcome.** The embedding stage is classified before the per-file-failure check, so the embedding stage still runs when the indexer recorded individual file failures and `seek sync --json` no longer reports `embeddings: "not_run"` for a run that embedded or deliberately skipped chunks.
- **`seek_capabilities`.** A configured client whose endpoint the `privacy.offline_only` policy refuses to reach is treated as unavailable, matching the sync report.
- **`seek sync <collection> --path`.** Restored the `%w` error chain, stopped printing the "validated inside collection" summary when the path guard rejected the run, and kept the empty-index hint off filtered invocations.
- **MCP `seek_search`.** Tolerates empty-string list arguments (`collections`, `fields`, …) emitted by some clients instead of failing the call, and honors `sort_by`/`sort_order` — `_score` maps to relevance order and a non-descending `sort_order` with `_score` is rejected.
- **Semantic service startup (issue #95).** `NUMBA_DISABLE_JIT=1` is exported (via `setdefault`, so a user-set value wins) before importing the service, avoiding the JIT warm-up stall. The tagger uses PCA rather than UMAP at runtime, so no hot path regresses; `tools/` and the bundled skill mirror are updated in sync.

## Performance

- **Agent hook target matching** (`internal/agenthooks`) memoizes the compiled target-hook regexes instead of rebuilding them on every invocation, with a benchmark guarding the cache.

## Validation

- Full test suite, `go vet`, and `gofmt` verified with CGO and FTS5 tags (`-tags "fts5 sqlite_fts5"`); the release gate re-runs them in CI before publishing.
- New coverage includes MCP argument-parsing tests, sync-outcome tests, a schema-driven parser availability test, and the issue #98 analyzer/end-to-end regression tests.

## Upgrade notes

- No migration or configuration change is required.
- If `NUMBA_DISABLE_JIT` is already set in your environment it is respected; otherwise the semantic service now exports it for a much faster startup.
