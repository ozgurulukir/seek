# seek v0.5.10

## Highlights

- **Second code-review verification pass:** every finding from a fresh multi-agent review was re-verified against the current code; the nine that still held are fixed here, each with a regression test. (The rest were confirmed already fixed or intentional.)
- **Optional Python services ship with the skill:** the semantic tagger, embedding server, and flashrank reranker are packaged inside the `seek` skill/plugin with setup scripts, so agents can stand up the optional NLP endpoints without cloning the repo.

## Fixes

- **Agent hooks (crash):** a hand-edited settings file containing the literal JSON `null` returned a nil map from `ReadSettings`, panicking hook install/repair on first assignment. It is now treated as an empty writable settings map (missing-file contract); invalid JSON still errors with the file name.
- **Windows service (quoting/injection):** the Task Scheduler task was registered as `cmd.exe /c ""<bin>" sync"` with the binary path interpolated unescaped — `%VAR%` expands even inside cmd.exe double quotes and an embedded quote breaks the quoting. The task action is now a plainly quoted argv (`"<bin>" sync`) launched via CreateProcess.
- **Semantic enrichment (churn):** a transient semantic-service `/health` failure used to degrade the enrichment fingerprint basis to an empty capability set. That basis mismatches every persisted fingerprint, re-selecting the whole collection for re-enrichment — twice (this pass and the next healthy one) with a half-up service, and the degraded basis was memoized for the process lifetime. A health failure is now an error: backfill warns and no-ops the pass, the sync path records nothing (documents keep their previous fingerprint) and warns once per process/provider.
- **Vector index (cancellation safety):** cancelling an embedding-space reset (Ctrl-C) also cancelled the vector-index restore, leaving the live HNSW index empty for the rest of the process while SQLite still held the embeddings — an empty graph a normal `Close` would then persist. The restore now runs with a cancellation-proof context.
- **Indexer (race hardening):** `WithLogger` is called per operation (sync, backfill) on the shared Runtime-owned Indexer; the logger swap is now guarded by the instance mutex like every other shared field.
- **xberg extractor (robustness):** extraction responses were read with an unbounded `io.ReadAll`; a broken or hostile server could OOM the sync. Response bodies are now capped at 64 MiB with an explicit over-cap error.
- **MCP (version reporting):** the MCP server hardcoded version `"dev"`, so release builds misreported themselves. Version/commit now live in `internal/buildinfo`, injected via ldflags, and are reported by both `seek --version` and the MCP server identity.
- **Search (actionable errors):** field-scoped query terms are validated against the FTS columns (`title`, `content`) at parse time. Unknown fields previously failed at query time as an opaque FTS5 `no such column` — or, in hybrid mode, silently killed the BM25 leg while vector results kept flowing. They now fail fast with `unknown field "x" (supported: title, content)`.
- **Docs:** corrected the stale "SyncVectorIndex clears the index" description in AGENTS.md (full sync builds off to the side and atomically publishes).

## Validation

- Full test suite, `go vet`, and `gofmt` verified with CGO and FTS5 tags (`-tags "fts5 sqlite_fts5"`); release gate re-runs them in CI before publishing.
- Regression tests added: JSON-null settings, Windows task action rendering, semantic health-failure no-op contract, bm25 title-weight ranking, xberg response cap, unknown-field sentinel propagation.

## Upgrade notes

- **Windows `seek service` users:** re-run `seek service stop && seek service start` once to re-register the task with the safer action string. The previously registered cmd.exe-based task keeps working; it is just deprecated.
- **Search queries:** query strings using unsupported `field:value` prefixes (e.g. `tags:go`) now fail with a parse error instead of a runtime FTS5 error. Use `seek search --field tags:go` for fast-field filtering — behaviour of `title:`/`content:` is unchanged.
- Patch release: drop-in binary replacement. No index schema migrations or vector space changes required.
