# seek v0.6.0

## Highlights

- **Documented config keys now do what they say.** A wiring audit found five config keys that were parsed from `config.yaml` but never consumed — `search.default_limit`, `filters.enabled`, `filters.default_collection`, `aggregations.enabled`, and `rerank.top_n` — and wires them into the shared search planner (so CLI and MCP behave identically) and the rerank client.
- **Scanned PDFs no longer fail silently.** Per-page OCR failures, embedded-text extraction failures, and textless pages without OCR enabled now surface as counted `WARN` lines in the sync summary, instead of indexing image-only pages with zero text and no signal.
- **The built-in xberg endpoint default pointed at the wrong service.** `DefaultXbergBaseURL` targeted port 8000 — that's `flashrank_server`'s port; the xberg server binds 8001. With `extractor.backend: xberg` and default config, extract requests went to the reranker.

## Added

- **`search.default_limit`** resolves the result limit when neither `seek search -l` nor the MCP `seek_search` `limit` argument specifies one (default 10, as before).
- **`filters.enabled` + `filters.default_collection`** apply a default collection filter when a request names no collection/repo. An unknown collection name errors with `seek collection list` guidance instead of silently blinding every search to zero results.
- **`aggregations.enabled: false`** now gates `seek search --aggs` and the MCP `aggs` argument with an actionable error (default `true` — no change unless opted out).
- **`rerank.top_n`** caps how many candidate hits reach the cross-encoder endpoint. Truncation is a prefix cut, so reranked result indices stay aligned with the caller's candidate slice (pinned by test).
- **Extraction warnings** (`extractor.Result.Warnings`) are logged per document by both indexer extraction call sites and count toward the sync report's warning total.

## Changed

- **`vector_index.hnsw.dimension` removed.** The HNSW index dimension always followed `embedding.dimensions`; the key was a silent no-op that implied an override existed. It (and its default constant) is gone. A leftover key in an existing config is simply ignored.
- **`rerank.top_n` is uncapped when unset.** The config loader no longer forces a default of 10 — `0` means rerank the full candidate pool. Users who set `top_n` while it was dormant will now actually get the cap; `seek auth status` prints `top_n: auto` when uncapped.

## Fixed

- **xberg default endpoint port:** `http://127.0.0.1:8000` → `http://127.0.0.1:8001` to match `tools/xberg_server/server.py`.

## Documentation

- Fact-check pass across README, AGENTS.md, `docs/`, and the bundled skill: Go version (1.25) and LOC counts, the background service description (it schedules a single `seek sync`; embedding runs in-process), `seek status`/`seek rm` described as standalone commands rather than aliases, the missing `hermes` parser schema row, codex's `archived_sessions` path, `lz4` in the compression algorithm list, and a stale `-l` reference in the analyze-lang section of `docs/local-setup.md`. `plugin.json` now tracks the release version.

## Tests

- New planner tests pin the limit resolution chain, `filters.default_collection` (applied / overridden / disabled), and the aggregations gate against a real temp SQLite store.
- `TestRerankTopNCapsCandidatePool` drives the provider factory through an httptest endpoint and asserts the candidate cap plus index alignment.
- Golden help snapshots regenerated for the reworked `-l` flag help.

## Validation

- Full test suite, `go vet`, and `gofmt` verified with CGO and FTS5 tags (`-tags "fts5 sqlite_fts5"`); the release gate re-runs them in CI before publishing.
- The wiring change passed a two-agent review (behavior review plus a silent-failure audit); all findings from that review are included in this release.

## Upgrade notes

- No migration is required. Defaults are unchanged: default limit stays 10, filters and aggregations are enabled, `top_n` unset behaves as before.
- If you previously set `rerank.top_n` or `filters.default_collection` while they were inert, they are active now — double-check the values against what you intend.
- Remove `vector_index.hnsw.dimension` from `config.yaml` at your leisure; it is ignored.
